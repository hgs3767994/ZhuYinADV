# 《聲音迷宮》地圖與美術製作紀錄

本文件是《聲音迷宮》地圖製作、圖片生成、程式整合與手機實測的專用工作紀錄。玩法規則仍以 [`CAMPAIGN_MODE_SPEC.md`](./CAMPAIGN_MODE_SPEC.md) 為準；本文件只補充地圖、美術、圖層、座標及資產版本，不以尚未確認的視覺提案覆蓋既定玩法。

## 文件使用規則

- 每項內容標示為「已確認」、「建議案」、「待討論」或「已淘汰」。
- 圖片生成前先確認用途、構圖、視角、畫風、色彩、尺寸、透明需求及不得出現的內容。
- 草圖、風格測試與正式素材分開保存；未經確認的生成圖不得直接覆蓋程式中的正式素材。
- 每輪只集中修改少量明確項目，避免修正單一內容時讓已確認部分漂移。
- 專案要使用的最終圖片必須保存到工作區；不得只留在圖片生成工具的預設輸出位置。
- 正式資產使用穩定、具用途的英文檔名；未定案版本使用 `-draft-vN` 或 `-concept-vN` 後綴。
- 替換既有正式資產前，需明確確認該圖是「取代」而非「新增版本」。
- 每次整合後分別記錄桌面瀏覽器、手機瀏覽器及公開部署的驗證結果。

## 製作範圍

### 第一階段：第2關「迷霧之路」

狀態：第2關灰盒、手機互動及美術工程均已確認並結案。原完整底圖 `level-02-base-map-v02` 保留作為畫風參考；正式場景使用可超出鏡頭的森林地表，以及預先烘焙、與森林底色合成的 PNG 道路狀態圖。五個岔路、錯路紫霧、三枚碎片與終點光門均已整合，並完成 Android 手機及 iPad 完整流程實測。

已確認的玩法條件：

- 使用《聲音迷宮》的純岔路配置，不使用符文門。
- 全程只顯示角色附近的局部區域，不顯示完整地圖，也不設小地圖。
- 共5個主要岔路，每個岔路提供2條顯示注音符號的候選道路。
- 五個正解依序使用 `ㄧ、ㄨ、ㄩ、ㄚ、ㄛ`，每個符號在該局作為正解一次。
- 玩家收集3枚聲音碎片後才能找到並啟用出口。
- 選錯時進入短死路，之後自動返回原岔路；不扣生命，但計入錯誤路線次數。
- 走過的道路不保留足跡或地圖記號；錯路返回後只把該道路的注音按鈕改為灰色，不得揭露未探索區域。
- 玩家點擊目前可到達的道路或節點後，鏡頭沿道路自動移動，不使用虛擬搖桿。
- 鏡頭移動或判定動畫期間鎖定其他輸入。
- 關卡採線性自動前進，不提供返回前一個岔路或符文門的操作。
- 迷宮沒有作答倒數，也不會因錯誤次數而戰敗。
- 拓樸、碎片位置與出口位置固定；每局可以更換題目符號及正確選項位置。
- 第一、第二、第三枚碎片各有既定的劇情光效；碎片不形成永久道具或額外資源。

### 第二階段：第7關「地下秘道」

狀態：暫不製作，待第2關引擎、鏡頭與局部視野驗證完成後沿用。

已確認差異：

- 使用符文門，不使用第2關的純道路岔路呈現。
- 共6個主要判定節點，主要使用3個候選符文門。
- 加入 `ㄅ、ㄉ`，並依既定題庫規則安排新符號出現順序。
- 環境主題是地下秘道，不能只把第2關的地表迷霧地圖換色。

## 圖層規劃

以下圖層架構已隨灰盒及手機互動原型確認。

### 1. 固定底圖

可包含：

- 地面與道路表面。
- 不影響路線隨機判定的固定樹木、草叢、岩石與遺跡。
- 岔路周邊的固定環境裝飾。
- 畫面邊界外的自然延伸區，避免鏡頭移動時露出空白。

不得包含：

- 玩家角色或 NPC。
- 注音答案符號。
- 聲音碎片及已收集狀態。
- 答錯與已探索狀態提示。
- 會隨狀態啟用的出口光效。
- 完整迷霧遮罩。

### 2. 程式動態層

- 代表玩家邏輯位置的鏡頭座標與道路移動路徑；遊戲中不繪製玩家角色或常駐位置標記。
- 注音符號、可點擊區與選擇回饋。
- `sound-fragment-large.png` 及收集動畫。
- 錯路返回後的灰色注音按鈕狀態；不另外繪製足跡、已探索道路或錯誤死路記號。
- 出口未啟用、啟用及完成狀態。
- 局部視野、迷霧遮罩及必要的霧氣動畫。
- 互動鎖定、成功與錯誤回饋。

### 3. 透明前景層

- 鏡頭經過時會從畫面邊緣掠過的樹冠、藤蔓、拱門或高岩石。
- 所有前景物件都必須避開關鍵符號與主要點擊區，或在程式中明確設定不攔截點擊。

## 尺寸與座標

正式工作畫布與座標規格已確認，且鏡頭安全區已完成手機實測：

- 優先以手機直向畫面設計，遊戲內容最大寬度為430 CSS px。
- 第2關正式工作畫布使用 `1280 × 4720 px`、2倍像素密度，相當於 `640 × 2360 CSS px` 的地圖世界。
- 入口在下、出口在上，透過上下推進及左右交錯的曲線道路善用直向螢幕。
- 所有節點與互動錨點以相對座標保存，避免素材縮放後必須重做題目或點擊資料。
- 視覺道路可以小於點擊範圍，但有效點擊區不得小於約48 CSS px。
- 底圖與前景圖必須使用完全相同的畫布尺寸及原點。
- 大型不透明底圖優先使用 WebP；需要透明的前景或元件使用能保留 alpha 的 PNG 或 WebP。
- 最終尺寸、格式與檔案大小上限會在風格測試圖確認後補入。

第一批透明道路與獨立元件使用下列正式工作尺寸（均為2倍像素密度）：

- 可平鋪道路材質：`1024 × 1024 px`，之後由程式沿既定SVG道路曲線裁切，不改動灰盒路徑座標。
- 王國石碑：`144 × 136 px`。
- 灌木木柵：`180 × 140 px`。
- 傾斜路標：`164 × 200 px`。
- 蕨類岩石：`200 × 160 px`。
- 破損小拱門：`188 × 216 px`。
- 魔法紫霧牆：`192 × 180 px`。

五個地標與紫霧牆均保留透明alpha與安全留白；地標不得攔截點擊，紫霧牆維持柔和、低飽和且不以強光暗示答案。

## 第2關灰盒的已確認分區

以下配置作為 `level-02-greybox-v02` 與後續正式美術的結構基準：

1. 入口區：從王國大門後方進入迷霧道路。
2. 岔路1：通過後取得第一枚聲音碎片。
3. 岔路2：加強局部視野與已探索道路的理解。
4. 岔路3：通過後取得第二枚聲音碎片，短暫顯示遠處道路輪廓。
5. 岔路4：提高道路方向變化，但仍只有兩個選項。
6. 岔路5：通過後取得第三枚聲音碎片並啟用出口指引。
7. 出口區：離開迷霧並銜接村落劇情。

每個岔路的兩條候選道路在作答前都必須看起來可能繼續前進。不能讓玩家僅憑道路是否明顯為死路判斷正解；真正的短死路終點需藏在尚未探索的迷霧中。

## 圖片生成品質檢查

每張候選圖至少檢查：

- 是否維持一致的俯視或斜俯視角，不在同一張圖中混用視角。
- 兩條候選道路是否同樣清楚且不提前洩漏正解。
- 道路寬度是否足以清楚呈現移動方向與點擊提示。
- 迷霧是否保留兒童遊戲的溫暖感，不過度陰暗、恐怖或寫實。
- 關鍵道路是否不被樹木、岩石、前景或霧氣永久遮住。
- 是否沒有不可控制的文字、符號、浮水印或多餘角色。
- 重複材質、扭曲物件、錯誤透視及不自然接縫是否在手機尺寸仍可見。
- 縮放與裁切後是否仍能和上方資訊列、下方提示文字共存。
- 透明素材是否具有乾淨 alpha 邊緣，沒有白邊或深色髒邊。

## 已確認的視覺規格

### 已確認：第2關視覺主題與環境氣氛

採用「迷霧籠罩的王國外圍森林」為主，加入少量「荒廢的王國郊道」敘事元素：

- 場景位於穿過王國大門後、抵達村落前的森林道路。
- 畫風採童話繪本式遊戲插畫，輪廓清楚、柔和、不寫實。
- 時段採陰天白晝或柔和清晨，不製作成夜景。
- 地面以暖米黃色土路為主，周圍使用深淺不同的森林綠與藍綠色植被。
- 迷霧使用帶薄荷感的淡藍灰色，表達魔法異常但不形成陰森恐怖氣氛。
- 聲音碎片及注音水晶相關效果以青藍與暖金作為亮點。
- 場景只加入少量傾斜路牌、破損藍金旗幟或王國石碑，不鋪滿廢墟。
- 第三枚碎片取得前不顯示村落位置；取得後才在出口方向出現柔和暖黃色光芒。
- 避免黑暗恐怖森林、尖銳枯樹、大量墓碑、寫實濃霧、大量發光水晶，以及直接畫入底圖的注音符號。

### 已確認：玩家視點、地圖視角與移動方式

採用玩家不出現在畫面中的「高角度探索鏡頭」，而非顯示角色標記或傳統具有地平線的第一人稱視角：

- 以鏡頭沿道路平移表達前進、進入短死路及由死路返回；不提供返回已通過岔路的操作。
- 鏡頭任何時候都不旋轉、不縮放、不晃動；答錯時也不以震動畫面作為回饋，視野方向保持穩定。

### 已確認：遊戲視窗、岔路固定構圖與迷霧範圍

遊戲視窗與停在岔路時的起始灰盒規格如下；數值先用於互動原型，手機實測後才能定為正式美術尺寸：

- 地圖視窗寬度使用 `min(100%, 390px)`，並固定為 `3:4` 長寬比；在390 CSS px寬的手機版面中高度為520 CSS px，使迷宮地圖填滿主要遊戲區域並減少下方留白。
- 地圖視窗不接受手動拖曳或捲動；位置變化完全由遊戲鏡頭控制。較矮裝置可讓整個遊戲內容垂直捲動，但地圖內部不可捲動。
- 岔路停點以畫面百分比配置：岔路中心約在 `x 50%、y 62%`；左右注音中心約在 `x 28%、y 36%` 與 `x 72%、y 36%`；左右道路分別在畫面頂部約 `x 16～20%` 與 `x 80～84%` 進入迷霧；已探索來路從畫面下方中央進入岔路。
- 道路視覺寬度使用56～68 CSS px，有效點擊寬度至少72 CSS px；注音符號圓牌使用58～64 CSS px；岔路中心保留約130～150 CSS px的清楚空間。
- 點擊候選道路或其注音符號都算選擇，不要求玩家精準點中字形。
- 角色可視核心改為固定在視窗中央偏下的圓角方形：寬約視窗84%、長寬比1:1、左右各留約8%、下方留約7%，圓角約52 CSS px；核心的上、左、右、下四邊統一使用內外霧影及16 CSS px模糊羽化，不得留下垂直或水平硬邊。核心之外維持約94%的淡藍灰濃霧，上方全寬答案遮蔽霧幕仍為獨立圖層。
- 迷霧遮罩固定在遊戲視窗，地圖在其下方移動。關卡不顯示走過道路的足跡；迷霧也不因探索過而永久消失。
- 候選道路前段必須清楚，後段及終點藏在霧中；選擇前不能看見短死路終點或下一個主要節點。
- 選錯後，鏡頭沿道路移至被倒木、岩石或濃霧阻斷的位置，播放錯誤回饋並停留約600～800毫秒，再沿原路返回；返回後不留下淡霧記號，但該道路的注音選擇按鈕改為灰色，表示已探索過的錯路，全程不晃動畫面。

### 已確認：五個岔路拓樸、碎片位置與動態死路

已確認的基本架構：

- 使用五個左右交錯的雙路匯合岔路；每個岔路的兩條道路都繞過中央環境物件，再於迷霧後方匯合。
- 第1、3、5個岔路的共同匯合點後方放置聲音碎片，使碎片位置不受當局正確道路位於左側或右側影響。
- 每個岔路的左右道路各拆成前段與後段獨立圖層；停在岔路時只顯示兩條外觀合理、寬度與可見距離相近的前段。
- 程式依每局題目把可左右交換的魔法濃霧牆放在錯誤道路的獨立死路深處；錯路不再沿正確道路後段朝共同匯合點彎回，牆後道路不建立，正確道路則在選定後建立後段並前往共同匯合點。
- 左右道路前後段、魔法濃霧牆、注音符號及點擊區都屬於可獨立控制的動態圖層，不合併畫入固定底圖。

- 選錯時，正確道路前段在鏡頭開始移動時淡出；錯誤道路只繪製到魔法濃霧牆，牆後道路完全不建立。鏡頭返回岔路後，正確道路前段重新淡入。
- 選對時，錯誤道路前段在鏡頭開始移動時淡出，正確道路後段及連接道路才在濃霧內建立；通過匯合點時不存在另一側道路可被看見。
- 未選道路以正向白色遮罩本身的透明度同步淡出，不再用黑色減法遮罩挖除；因此岔路交界不會留下缺角，遠端也不會殘留道路尾端。
- 聲音碎片只在玩家已選中正確道路、且鏡頭距離碎片250邏輯像素內才建立；錯路移動期間不會提前看見匯合點碎片。
- 第1、3、5個岔路遇到碎片時，鏡頭停下約1.65秒：光點先飛向畫面下方中央，接著畫面中央顯示大碎片，向上再向下跳動一次後淡出，動畫完成才繼續前進。
- 鏡頭抵達匯合點並進入一般連接道路前，先在全寬濃霧後方建立下一個岔路的兩條道路前段及中央環境物件；互動按鈕與下一題語音仍只在真正抵達後啟用，避免道路突然跳出。
- 流程線性自動前進，不顯示道路足跡、返回上一個岔路、返回上一道符文門或沿道路前進的操作按鈕。
- 互動按鈕使用至少64 CSS px的圓形觸控面積；地圖視窗採 `3:4` 長寬比，在390 CSS px寬的手機版面中實測為390×520 CSS px。
- 「減少動態效果」沿用全站規則，鏡頭與碎片動畫縮短至近乎立即完成。

主要程式位置：

- `src/components/SoundMazeMapViewport.tsx`：地圖、鏡頭、霧層、選路與動態物件呈現。
- `src/components/SoundMazeGame.tsx`：答題、鏡頭時序、錯路返回、碎片與完成流程。
- `src/game/soundMaze.ts`：穩定題目ID、左右道路及第2關地圖錨點。
- `src/styles.css`：手機視窗、霧層、觸控區與動畫。
